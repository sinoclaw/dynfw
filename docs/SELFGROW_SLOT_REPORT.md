# Self-growing-slot 探针报告 —— 固定 D 训练中动态涨 slot 数 N 能否优于一给满？

> 脚本：`experiments/scaling/selfgrow_slot.py` · 数据：`results/v0.0.1/selfgrow_slot.json` · CPU 口径 · 3 seed
> 动机：外部 GPT 审计（仅本地存档 `docs/GPT_AUDIT_GROWTH.md`）提出 FusedFW 自生长应走
> **"固定 D + 训练中动态涨 slot 数 N"**（而非宽度 D 扩宽+继承，后者已证 No-Go）。本报告在 CPU 上验证其核心假说。

## 问题
**固定 D 的 FusedFW，训练中自主 spawn 新 slot，能否在"同最终参数 + 同预算"下比"一开始就给满 slot 数"获得更好/不降的 loss？**

## 设计（判据先行，一次一组变量，P0 seed-先建）
D=96 固定，k=16，use_ffn=True，唯一被动的变量 = slot 数 N。
| 路径 | 设计 | 最终 N | 说明 |
|---|---|---|---|
| **Fixed-96** | N=96 从零训 300 | 96 | "一开始给满"基线 |
| Fixed-32 | N=32 从零训 300 | 32 | 检查小容量是否受限 |
| **GrowA** | N=32 训150 → 涨到96(新槽fresh-init) → 全模型续训150 | 96 | GPT"新槽独立学"轻量版(不冻结) |
| **GrowB** | 同 GrowA，但涨后**冻结旧槽行梯度** | 96 | GPT"旧能力参数完全不动" |

同数据 / 同 val / 同 token budget(300 步) / 同最终 N=96(同最终参数) / 3 seed。

## 结果（mean±std，3 seed）
| 路径 | val | 距 Fixed-96 | 最终参数 |
|---|---|---|---|
| **Fixed-96** | **3.191 ± 0.006** | — | ~151K |
| **GrowA(全参续训)** | 3.245 ± 0.008 | **+0.054** | ~151K |
| **GrowB(冻结旧槽)** | 3.269 ± 0.007 | **+0.078** | ~151K |
| Fixed-32 | 3.250 ± 0.014 | +0.059 | ~139K |

std 0.006-0.014 → **GrowA/B 都明确劣于 Fixed-96（差距远超噪声）。**

## 结论（诚实、决定性）
**GPT 的"自生长 slot 优于一给满"假说在 CPU 上未获支持（No-Go）。**

1. **GrowA(+0.054) 与 GrowB(+0.078) 都打不过 Fixed-96**——即使同最终参数(151K)、同预算(300步)、且 Grow 前半程更省算力。
2. **GPT 的"容量压力"前提是真的但救不了**：Fixed-32(3.250) 明显差于 Fixed-96(3.191) → **N=32 确实容量受限**（residual/使用率压力确实存在，GPT 的 spawn 触发信号成立）；**但成长并不能换来"比一给满更好"** —— 该压力下最优解仍是"直接给 96 并训满"。
3. **机理（来自 val 曲线，与宽度 No-Go 同源）= 预算机会成本 + 小规模阶段不迁移**：
   - GrowA 只给最终 N=96 **150 步**（B2），Fixed-96 给满 **300 步**。
   - 成长模型起点更优（GrowA 的 B2 第30步≈3.59，≈Fixed-96 第150步≈3.58）——**warmstart 优势真实存在**；
   - 但 Growth 只在 N=96 上训 150 步 = **对最终架构"欠训练"**，被 Fixed-96 的 300 步反超。
   - **在 N=32 上花的 150 步对最终 N=96 模型基本"白花"**（学的是 32-slot 格局的解，涨到 96 后要重新适配）。
4. **GrowB（GPT 字面"旧参数完全不动"——冻结旧槽）最差(+0.078)**：冻结将旧 32 槽锁死在 32-slot 格局的最优解，无法再适配 96-slot 格局 → 反而最伤。**"冻结旧"在本场景是负收益。**

## 与既有结论统一（第 3 个独立 growth No-Go）
| growth 形式 | 结果 |
|---|---|
| 宽度 D 扩宽 + 权重继承（`07d4fa6`） | B−A=+0.165，No-Go |
| **slot 数 N 涨 + fresh-init（本实验）** | GrowA +0.054 / GrowB +0.078，**No-Go** |
| GSLM/FDN 节点增长 | No-Go（容量饱和/增长不产生独立能力） |

**⇒ FusedFW 是固定结构架构，"训练中把它长大"（无论宽 D 还是槽数 N 还是节点）都不优于"一开始按目标规模配满容量"。FusedFW 的价值 = 固定规模下的"能力相当/略优 + O(T) + decode 便宜"，不是成长。DynFW 卖点维持"固定规模高效"，不宣传"从小长到大"（非独有短板，Transformer 亦然）。**

## 边界
- 只测了**单次增长（32→96）**与**单个任务(char-LM)**；未测多级增长/更细 spawn 策略/真实多任务（那才是 GPT 蓝图里"长错了就剪/能力池"的完整版）。但**"成长不优于一给满"的方向已清晰且稳健（3 seed 稳）**。
- 结论是本实验口径（同预算固定 300 步）；若给 Grow 更多步（比如也 300 步花在 N=96 上）则 Grow 会更接近 Fixed-96——但那等于"多给预算"，不是"成长红利"，属预算问题非机制优势。

## 下一步建议
**growth 这条（宽度/槽数/节点）全部关掉**，不再投入。主线回到**真实模型蒸馏 benchmark（需 GPU）**——那才是回答"FusedFW 能否替代 Transformer"的关键。若要看 GPT 完整蓝图（多级生长 + 长错剪 + 多任务能力池），那属于 DCA 独立线程，与"FusedFW 自己长"是两回事，等主线有答案再评估。
