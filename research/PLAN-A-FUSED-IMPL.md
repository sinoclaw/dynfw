# 方案 A：FWAttention 融合实现 —— 跑前锁定的判据（2026-09-11）

## 要回答的问题
「我们的 O(T) 省算力卖点**能不能兑现**」—— FLOPs 层面 O(T) 已实测成立（MACs 精确线性），
但墙钟全区间输 TF 2.4~6.5×，根因已定位为实现形态（Python 分块循环 + 强制 fp32 + 无融合注意力）。

## 改动范围（铁律）
- **基线文件 `dynfw/models/fused_fw_fw_cycle.py` 一行不动**（已 git 提交，有回滚点 d44e189）
- 优化版写成**新文件** `dynfw/models/fused_fw_fw_cycle_opt.py`，只换实现形态、**不改数学**

## 优化清单（逐条对应 profile 定位的根因）
| # | 优化 | 对应 profile 证据 |
|---|---|---|
| 1 | 块内注意改 `F.scaled_dot_product_attention(is_causal=True)` | 原：无任何融合调用；TF：3 次 FlashAttention/2.6ms |
| 2 | 去掉 5 处 `.float()` 强制转换，全程 bf16 | `aten::copy_` 2610 次 / 38.2ms（TF 420 次 / 10.4ms） |

## 判据（跑之前写死，跑后逐条如实对照）

### J1 正确性（不过则一切作废）
- **因果性探针**：`probe_causality_all.py` 优化版 maxdiff 必须 = 0
- **数值等价**：同权重、同输入，优化版 vs 基线 logits maxdiff
  - 只做 #1/#3/#4/#5（保留 fp32）→ 要求 **< 1e-2**（bf16 归约顺序差）
  - 做 #2（全 bf16）→ 允许 < 1e-1，但**必须单独标注为「数值有变的版本」**

### J2 性能（主判据）
在 **T=8192 / 16384** 两档测 ms/step，与 TF 比：

| 结果 | 判定 |
|---|---|
| 我们 **< TF 的 1/1.5**（即快 1.5× 以上） | ✅ 卖点成立，值得工程化 |
| 在 TF 的 0.8~1.5× 之间（打平） | ⚠️ 未兑现，但差距已可优化 → 再迭代一轮 |
| **> TF 的 1/2**（仍慢 2× 以上） | ❌ **卖点不成立，建议砍掉** |

### J3 能力不损（新机制变更必查）
- 同 seed、同预算短训（2000 步）→ 优化版 val loss 与基线差**必须 < 0.02 nats**（噪声内）
- 超出即说明优化改了模型语义，不得当「同一模型」使用

### J4 诚实条款
- 三条判据任一不过 → **照实报，不找补、不改判据**
- 只报墙钟与实测，**不得只报 MACs/FLOPs**
- 若最终结论是「兑不了」，直接说放弃这条卖点
